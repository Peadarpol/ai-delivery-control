## PRE-EXECUTION FINDINGS (verified against live code 2026-06-14)

### HIB-055 — universal RULE sections orphaned from `active_sections`
- `load_review_context(diff)` (`src/scripts/ai_review.py`) reads `UNIVERSAL_CONTEXT_FILE` and
  `PROJECT_CONTEXT_FILE`, concatenates (`combined = universal + "\n\n" + project`), and returns
  `_select_context_sections(diff, combined)` when a diff is present.
- `_select_context_sections` seeds `active_sections = {"micro_checks"}` and adds a section only
  when a `trigger_map` pattern matches. `trigger_map` keys are the six project-capability names
  (`transactional_integrity, branch_isolation, mass_assignment, rbac, migrations, clean_arch`),
  which match none of the universal section IDs (`secrets, tdd_law, database_bypass, clean_code,
  dependencies, micro_checks, vocabulary`). All universal RULE sections carry a marker but aren't
  in `active_sections`, so they're dropped. Only `micro_checks` survives.
- `_get_active_context_sections(diff)` (end of file) duplicates `trigger_map` for snapshot logging
  and must stay consistent with any change.
- **CONSTRAINT-01 tension:** injected context competes against the ≤2,000-tok gate budget alongside
  `repo_map` (capped `repo_map[:2400]` ≈ 600 tok) and `adr_context` (capped `[:1600]` ≈ 400 tok),
  both in `_run_review`. The five RULE sections are ~250 tok; the `vocabulary` section
  (`review_context_universal.md` lines ~65–159) is ~650–700 tok. Naive always-inject-all risks a
  budget collision on ADR commits — hence Shape B.

### HIB-053b — spec-mtime false-success (`.agent/scripts/init_session.py`)
- In `infer_and_close_previous_session()`, the no-override/no-gemini-close inference branch: when
  `get_commits_after(prev_start)` is empty, it scans `docs/planning/specs/SPEC-*.md` and sets
  `spec_files_modified = True` if any spec's `mtime > prev_start_dt`. The `if commits or
  spec_files_modified:` block then records `outcome = "success"` ("Specification compiled/updated
  with no active commits") when there are no FAILs/open tasks.
- HIB-053's `_override_success_has_commit` guard does **not** cover this branch.
- Two defects: (1) false success with nothing committed; (2) mtime is unreliable (editor save,
  branch switch, the session-start `_create_session_checkpoint()` stash rewrite mtimes).
- Timing for the fix: in `main()`, `infer_and_close_previous_session()` runs **before**
  `initialize_session()` and `_create_session_checkpoint()`, so at inference time the working tree
  still reflects the previous session's real state — `git status --porcelain` on the specs path is
  a sound replacement for mtime. (Verify this during implementation.)
