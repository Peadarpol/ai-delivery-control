# Configuration Reference

`.agent/config.yaml` is the primary harness configuration file. It is generated by the
installer from `bootstrap/templates/config.yaml.template` and should be reviewed and
customised after install.

Re-running the installer regenerates this file — copy your customisations back across if
you re-run, or edit the template directly in the harness repo before installing. The file
is structured into eight sections, each documented below.

---

## 1. `project`

Basic project identity. Used in tool supplements, session tracing, and the harness wiki.

| Field | Type | Default | Example | Description |
|---|---|---|---|---|
| `project.name` | string | auto-detected | `"my-api"` | Read from `pyproject.toml` or `package.json`; falls back to directory name |
| `project.version` | string | auto-detected | `"1.2.0"` | Read from `pyproject.toml` or `package.json`; falls back to `"0.1.0"` |
| `project.type` | string | `"service"` | `"service"` | Informational — not used by gate logic |

## 3. `model_routing`

Controls which AI provider and model handles each task category, structured into role-based `review` and `budget` tiers. This topology-independent design allows routing low-cost tasks (like wiki compiling and classification) to either local models (e.g. Ollama) or low-cost cloud APIs (e.g. Claude Haiku or GPT-4o-mini).

| Field | Type | Default | Example | Description |
|---|---|---|---|---|
| `model_routing.review_provider` | string | `"anthropic"` | `"anthropic"` | Cloud/heavy provider for the AI review gate |
| `model_routing.review_model` | string | `"claude-sonnet-4-6"` | `"claude-opus-4-7"` | Heavy model for the AI review gate |
| `model_routing.wiki_compile_provider` | string | `"ollama"` | `"ollama"` | Default provider for local wiki compilation |
| `model_routing.budget_provider` | string | `"ollama"` | `"anthropic"` | Provider for low-cost tasks (Ollama, Anthropic, etc.) |
| `model_routing.budget_model` | string | `"gemma4"` | `"claude-haiku-4-5"` | Model for lower-cost or local tasks |
| `model_routing.budget_provider_timeout_seconds` | integer | `3` | `3` | Timeout in seconds for budget provider calls |
| `model_routing.budget_base_url` | string | `"http://localhost:11434"` | `"http://localhost:11434"` | Base URL for the budget model API (e.g. Ollama) |
| `model_routing.budget_tasks` | list | `[wiki_compile, ...]` | — | Task types routed to the budget model tier |

### 3.1 AI Review Overrides (`.ai-review-config.json`)

To support model diversification and fail-secure risk mitigation, the AI Adversarial Review Gate reads project-specific model and timeout overrides from `.ai-review-config.json` at the project root. This configuration overrides default settings in `providers.py` and `ai_review.py`:

```json
{
  "provider": "anthropic",
  "model": "claude-sonnet-4-6",
  "model_high_risk": "claude-opus-4-8",
  "timeout_seconds": 60
}
```

- **`provider`** (string): The LLM provider (e.g. `"anthropic"`, `"google"`, `"openai"`).
- **`model`** (string): The default model to run standard commits through (e.g. `"claude-sonnet-4-6"`).
- **`model_high_risk`** (string): The high-performance model to run high-risk commits through (e.g. `"claude-opus-4-8"`). High-risk commits include those containing migrations, database schemas, authentication, authorization, permissions, or transactional integrity layers.
- **`timeout_seconds`** (integer): The request timeout in seconds (default `60`). Recommend setting to `60` or higher when utilizing heavier models like Opus 4.8.

## 6. `domain_constraints`

A plain-English list of inviolable constraints injected into agent context at every session
start. Each string is read by `init_session.py` and treated as a hard rule the agent must
never violate.

```yaml
domain_constraints:
  - "Tenant Isolation: every operational table must be scoped to a tenant"
  - "RBAC: Admin, Staff, and User roles are the only valid principals"
  - "Soft-delete required on all user-facing entities"
```

The installer seeds three placeholder examples. Replace them with your project's actual
constraints before running the first AI session. For richer constraint documentation,
reference your `docs/decisions/business_rules.md` here and keep the list to high-level
reminders.

## 7. `agent_limits`

Operational circuit-breaker thresholds enforced by `.agent/scripts/circuit_breaker.py`.
Agents must check these limits before committing and escalate to the user if any is exceeded.

| Field | Type | Default | Description |
|---|---|---|---|
| `agent_limits.max_files_per_commit` | int | `15` | Commits touching more files than this require user review before proceeding |
| `agent_limits.max_test_retries` | int | `3` | After 3 identical test failures the agent must stop and escalate — do not retry indefinitely |
| `agent_limits.warn_session_minutes` | int | `120` | Agent alerts user when the session reaches this duration |
| `agent_limits.max_session_minutes` | int | `240` | Hard session time limit — agent must perform session close and stop |

## 8. `architecture`

Defines your project's layer boundaries, forbidden code patterns, and coupling thresholds.
These rules are enforced by `.agent/skills/senior-architect/scripts/architecture_checks.py`
on every pre-commit run.

### `architecture.layers`

Each entry defines a named architectural layer and the module prefixes it must not import.
The check scans every `.py` file under `path` and reports any `import` or `from ... import`
matching a forbidden prefix.

```yaml
architecture:
  layers:
    - name: domain
      path: "src/domain"
      forbidden_imports:
        - "src.infrastructure"
        - "src.presentation"
    - name: application
      path: "src/application"
      forbidden_imports:
        - "src.infrastructure"
        - "src.presentation"
    - name: infrastructure
      path: "src/infrastructure"
      forbidden_imports:
        - "src.presentation"
```

| Field | Type | Description |
|---|---|---|
| `layers[].name` | string | Layer name — used in error messages |
| `layers[].path` | string | Directory path for this layer (relative to project root) |
| `layers[].forbidden_imports` | list[string] | Module prefixes this layer must not import |

### Other `architecture` fields

| Field | Type | Default | Description |
|---|---|---|---|
| `architecture.forbidden_patterns` | list[string] | `[]` | Regex patterns banned anywhere in the codebase (e.g. `"os\\.system"`) |
| `architecture.aggregate_roots` | list[string] | `[]` | Base class names identifying domain aggregate roots |
| `architecture.coupling.thresholds.default.threshold` | int | `30` | Maximum coupling complexity score; files above this generate a warning |

### `memory`

Retention policy for session state files, applied by `retention_cleanup.py` (T1-I-06, roadmap).

| Field | Type | Default | Description |
|---|---|---|---|
| `memory.retention.session_ledger_retention_days` | int | `90` | Days to retain session ledger entries in the warm tier |
| `memory.retention.harness_events_retention_days` | int | `365` | Days to retain governance event records |
| `memory.retention.review_log_retention_days` | int | `90` | Days to retain AI review verdicts |
| `memory.retention.dream_proposals_reviewed_retention_days` | int | `365` | Days to retain reviewed dream proposals before archival |
