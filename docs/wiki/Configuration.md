# Configuration

`.agent/config.yaml` is the single configuration file for the harness. It is generated by the installer from a template and is safe to edit — your changes are preserved on upgrade.

---

## How it is used

The configuration file is read at:

- **Session start** — by `init_session.py` to load domain constraints and agent limits into context
- **Pre-commit time** — by `ai_review.py` and `architecture_checks.py` for capability routing and layer boundary enforcement
- **Workflow invocations** — by workflows and skills that reference stack-specific commands

---

## The eight sections

| Section | Purpose |
|---------|---------|
| `project` | Project name, version, and type |
| `tech_stack` | Language, framework, package manager, URLs, GitHub integration, document prefix conventions |
| `model_routing` | Which AI provider and model handles each task type |
| `capabilities` | Shell commands for database, test, lint, security, and run operations |
| `paths` | Source directories, test root, docs, scripts, and key document paths |
| `domain_constraints` | Plain-English inviolable constraints injected into agent context at every session |
| `agent_limits` | Circuit-breaker thresholds — max files per commit, test retries, session time limits |
| `architecture` | Layer boundary rules, forbidden import patterns, and coupling thresholds |

---

## The most important fields to set after install

### `domain_constraints`

Replace the installer's placeholder examples with your project's actual constraints before the first AI session. These strings are injected verbatim into the agent's context and into the AI review gate system prompt on every commit:

```yaml
domain_constraints:
  - "Tenant Isolation: every operational table must be scoped to a tenant"
  - "RBAC: Admin, Staff, and User roles are the only valid principals"
  - "Soft-delete required on all user-facing entities"
```

### `architecture.layers`

Define your codebase's layer boundaries. The architecture check AST-scans every commit for violations:

```yaml
architecture:
  layers:
    - name: domain
      path: "src/domain"
      forbidden_imports:
        - "src.infrastructure"
        - "src.presentation"
    - name: infrastructure
      path: "src/infrastructure"
      forbidden_imports:
        - "src.presentation"
```

### `model_routing`

Controls which provider handles the adversarial review gate vs cheaper tasks:

```yaml
model_routing:
  review_provider: "anthropic"
  review_model: "claude-sonnet-4-20250514"
  budget_provider: "ollama"
  budget_model: "gemma4"
  budget_base_url: "http://localhost:11434"
```

The `review` tier handles the adversarial gate. The `budget` tier handles wiki compilation, classification, and other low-cost tasks. If you do not have Ollama, set `budget_provider: "anthropic"` and `budget_model: "claude-haiku-4-5"`.

### `capabilities`

Shell commands for your stack, used by workflows and skills. The installer auto-populates these from stack detection — update them if your project uses non-standard commands:

```yaml
capabilities:
  db:
    migrate: "poetry run alembic upgrade head"
    rollback: "poetry run alembic downgrade -1"
  test:
    run_all: "poetry run pytest"
    type_check: "poetry run mypy"
  lint:
    check: "poetry run ruff check"
    fix: "poetry run ruff check --fix"
```

### `agent_limits`

Circuit-breaker thresholds enforced by `circuit_breaker.py`:

```yaml
agent_limits:
  max_files_per_commit: 15       # Commits above this require user review
  max_test_retries: 3            # Stop and escalate after 3 identical failures
  warn_session_minutes: 120      # Alert user at this duration
  max_session_minutes: 240       # Hard session time limit
```

## What you do not need to configure

- `project.name` and `project.version` — auto-detected from `pyproject.toml` or `package.json`
- `tech_stack.language`, `core_framework`, `package_manager`, `test_framework` — auto-detected by the installer
- `paths.source_root` and `paths.entrypoint` — auto-detected from project structure
